# Next.js + Tauri で創る近未来3D将棋アプリ『サイバー将棋 V3』開発記 — デスクトップ化とGPLライセンス設計の最適解

こんにちは！開発者の tztechno です。

今回は、WebAssembly（WASM）の将棋思考エンジンと次世代フロントエンド技術を組み合わせた、近未来3D将棋シミュレーター**『サイバー将棋 V3 Desktop Edition』**の開発舞台裏についてお届けします。

Next.jsで作られたWebアプリケーションをTauri（タウリ）を用いてデスクトップアプリ化し、商用（有料販売）するにあたって直面した**「UIレイアウト設計」「決済と安全な配信」「GPLライセンスへの準拠」**という3つの挑戦と、その解決策について技術的な観点から詳しく解説します。

---

## 1. 『サイバー将棋 V3』とは？

『サイバー将棋 V3』は、WebAssembly（WASM）としてビルドされた最強クラスの将棋思考エンジン（**やねうら王** & **Fairy-Stockfish**）を搭載した、完全ローカル動作の将棋シミュレーターです。

### 主な特徴
*   **没入感ある3DマトリックスUI**: 3Dホログラム空間を意識したサイバーパンクなデザイン。
*   **多彩なモード**: プレイヤー vs AI対局はもちろん、思考中の思考ログや評価値をリアルタイム表示しながら観戦できる「AI vs AI（対局観戦）」機能を搭載。
*   **マルチプラットフォーム**: Mac（Apple Silicon / Intel）, Windows, Linux, Android に対応。

---

## 2. フロントエンド設計とデスクトップ版の画面最適化

UIは **Next.js + Tailwind CSS** で構築されています。Web版からデスクトップ版へ移植するにあたり、以下のデスクトップ固有の課題をクリアしました。

### ① Webviewのズームコントロール機能の追加
デスクトップアプリ（Tauri）では、OSやディスプレイの解像度（DPI）によってUIが小さすぎたり大きすぎたりすることがあります。そこで、キーボードショートカットおよびヘッダーメニューから、アプリの表示スケールを動的にズームイン・ズームアウトできる機能を実装しました。これにより、どんなモニター環境でも最適なサイズで対局できます。

### ② 盤面シフトの防止とレイアウト分割の安定化
思考ログ（エンジンログ）や評価値グラフを表示する際、ログのテキスト量に応じて将棋盤の位置がガタついたりシフト（移動）したりする問題がありました。
これを防ぐため、盤面エリアとログパネルエリアを完全に独立したフレックス/グリッド・コンテナーに分割し、ログの更新がメインの盤面に影響を及ぼさない「スプリットレイアウト」を確立しました。

---

## 3. WebからTauri（デスクトップ）を選択した理由

Webブラウザ上で動作する将棋アプリには、いくつかの限界がありました。
1.  **ブラウザのメモリ・CPU制限**: WASMエンジンを動かす際、ブラウザのサンドボックス制限によりマルチスレッドや大容量メモリ（ハッシュテーブル）の確保に制約が生じる。
2.  **オフライン対応**: ユーザーが移動中やオフライン環境でも、ストレスなく強豪AIと対局させたい。

そこで、Electronよりも軽量・高速で、Rust製の安全なバックエンドを持つ **Tauri** をラッパーとして採用しました。Tauriはフロントエンドの静的HTML/JS（Next.jsの `output: 'export'`）をネイティブパッケージ（`.dmg` / `.msi`）に圧縮し、UIコードをバイナリ内部に完全に隠蔽できます。

## 4. GPLv3ライセンス準拠と商用化（クローズドソース）の設計

将棋エンジンの「やねうら王」や「Fairy-Stockfish」は、**GPLv3（GNU General Public License v3）**ライセンスで公開されています。

商用アプリとして「自作のUIや決済コードは非公開（クローズドソース）のまま有料販売したい」という要件と、GPLの「派生物のソースコード公開義務（コピーレフト効果）」をどのように両立させるかが最大の論点でした。

### ① 現行アプローチ：Web Workerによる疎結合とライセンス開示
現在リリースされている初期ビルドでは、WASM形式のエンジンをメインのスレッドから切り離し、**Web Worker（別スレッド）** 上で動作させています。
*   **通信の疎結合化**: フロントエンドのUIとエンジンは、直接的なAPI/関数呼び出しを行わず、標準的な **USI（Universal Shogi Interface）プロトコル** をベースにした非同期メッセージング（`postMessage`）のみでデータをやり取りしています。
*   **「単なる集積（Mere Aggregation）」の適用**: GPLv3第5項に基づき、独立した自作UIバイナリと、アセットとしてのGPLエンジンファイルを1つのインストーラーに同梱する形態をとることで、「単なる集積」としてUI部分のクローズドソースを維持しています。これは先行するモバイル将棋アプリ「きふみAI (kifumiai.com)」等と同様の法解釈アプローチです。
*   **適切なソースコード開示**: 販売LPおよびダウンロード完了ページにGPL準拠エリアを用意し、やねうら王とFairy-Stockfishの公式ソースコードリポジトリへのリンクを明記して配布義務をクリアしています。

### ② ロードマップ：Tauri「Sidecar」への移行による完全ホワイト化
WASM版での実行は移行がスムーズである一方、ブラウザのWebview上で動くため、CPUのAVX2/SSE4.2命令を直接利用できないという性能面の妥協がありました。

これを解決するため、次期バージョンに向けて **Tauriの「Sidecar（サイドカー）」機能** を使用したアーキテクチャへのアップデートを予定しています。

```mermaid
graph TD
    subgraph Tauri App (Process Boundary)
        UI[Next.js UI (Closed Source)]
        Rust[Rust Backend (Tauri)]
        UI -- tauri.invoke / events --> Rust
    end
    
    subgraph Independent OS Process
        Engine[Native Engine binary: YaneuraOu / Stockfish (GPLv3)]
    end
    
    Rust -- StdIn/StdOut (USI Protocol) --> Engine
```

*   **OSプロセスレベルの完全分離**: C++でネイティブビルドした思考エンジン（`.exe`やMac用バイナリ）をパッケージに同梱し、TauriのRust側からOSの子プロセスとして別プロセスで起動（spawn）します。
*   **標準入出力（stdin/stdout）連携**: 両者は完全に分離されたメモリ空間で動作し、標準入出力を介したUSI通信のみで連携します。
*   **完璧なライセンスクリアと超高速化**: この構成は、PC将棋GUIの大御所である「ShogiGUI」や「ShogiHome」と全く同一であり、GPLv3上のリスクを完全にゼロにできます。さらに、ネイティブ実行ファイルになることで、WASM版と比較して**数倍〜十数倍のネイティブ演算速度（AVX2命令・ネイティブマルチスレッド）を発揮**します。

## 5. Stripe + Netlify を使ったセキュアな決済・配信システム

デスクトップ版の有料販売（¥2,980）を実現するため、ECサイト（[04f_netlify_ec_store](file:///Users/shun_ishii/Projects/04f_netlify_ec_store)）も自作しました。

*   **Next.js App Router + Stripe API**: ユーザーがOS（Windows / macOS / Linux / Android）を選択して購入ボタンを押すと、NetlifyのサーバーレスAPIを経由してStripeの決済セッションを作成・チェックアウトへ遷移。
*   **セキュアなワンタイム・ダウンロードリンク**: 決済完了後、Stripe Webhookおよびセッション検証API（Next.js Route Handler）を介して支払い完了を確認し、動的に暗号化ディレクトリ内の静的バイナリへと一時的にリダイレクトします。これにより、未購入者による不正ダウンロードを防ぎつつ、高速なCDN配信を実現しました。
